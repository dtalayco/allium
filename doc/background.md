# Terminology, Context and Background for Allium

## Overview

This document accumulates background related to networking as relevant
to Allium.


## Concepts

In general, Allium assumes packet switched networks of hosts, although
this circuit switching systems should be addressed as well.

Packets: A mostly atomic container for data.

Framing: The mechanism delineating packets.

Device: A switch, host or appliance with network interfaces and which
may be controlled or inspected by an Allium controller.

Switch: A device focused on moving packets between network iterfaces.
This includes routers.

Device: A switch or host for which Allium has an operational model and
can, at least, inspect to get state and metrics.

Managed Device: A device to which Allium can send commands (as well as
inspect for state and metrics).

RO Device: (Read only). Used when we need to be explicit that the
device only supports inspection, not control or configuration.

Topology: A set of devices and their connections. There are some
templates, like spine-leaf, mesh, ring, but these are shortcuts.

Network: A physical or logical topology. Logical networks require some
protocol for defining the virtual connectivity (eg VLANs or Routing
Instance).

Host: A device which runs processes that produce and consume packets.

POP: A point of presence on the network which is a process running on
a host.

Flow: An ordered sequence of packets generated by one POP and destined
for one or more other POPs. The set of destinations is fixed for a
given flow.

Flow Requirements: What attributes are intended for the flow. Examples
include latency, jitter and acceptable drop rate.

Treatment: What actions are taken on a packet by a device. This
includes being dropped, prioritized relative to other packets, and any
modifications to the packet.

### Packets and Flows

With global knowledge, we could identify a set of flows and assign any
packet to a specific flow. However, switching devices have only the
packet itself, possibly some metadata (eg ingress port) and the state
of the device's forwarding logic (eg, tables) to associate a packet to
a flow. Viewing the problem as "How to achieve a consistent map from
packet instance to flow across all devices in a network" is difficult.

What we wish to achieve in the network is treatment of packets during
their transit across multiple devices resulting in the satisfaction of
the requirements for the packet's flow. Thus, we view each device as
applying a partial map from packet to the treatment of the packet and
ask if the patching of these partial functions (across multiple
devices) produces the desired treatment of flows across the network.
